# Ledger (web)

The installable web app. Plain ES modules, no build step, no dependencies —
open `index.html` through any static server and it runs.

```
web/
├── index.html              shell
├── manifest.webmanifest    home-screen install metadata
├── sw.js                   offline cache
├── css/styles.css
├── icons/                  generated by tools/make-icons.js
└── js/
    ├── app.js              router + shell
    ├── domain.js           data shapes and derived numbers (pure)
    ├── coach.js            progression engine — what weight to use next
    ├── ai.js               builds the briefing you paste into Claude
    ├── stats-free helpers  format.js, charts.js, ui.js, rest.js
    ├── db.js / store.js    IndexedDB and app state
    ├── library.js          the seeded exercise list
    ├── picker.js           exercise chooser overlay
    └── views/              one file per screen
```

## Conventions worth knowing

- **Weights are stored in kilograms.** `format.js` converts at the edges, so
  switching between lb and kg never alters what was logged.
- **`domain.js` is pure.** No DOM, no storage — every derived number (volume,
  estimated 1RM, weekly streaks) is a plain function over plain objects.
- **Views get a fresh container each render** (`app.js`). Delegated listeners
  attach to that container, so they're discarded with it. Attaching to a
  persistent element stacks a listener per visit — one tap then fires N times.
- **Typing never re-renders.** Weight, rep, and name fields call
  `store.mutateWorkoutSilently` / `saveRoutineSilently`, which mutate in place
  and write on a debounce. A re-render would blur the field mid-entry.
- **A workout document carries its entries and sets inline.** IndexedDB isn't
  relational and the UI always wants the whole session at once.
